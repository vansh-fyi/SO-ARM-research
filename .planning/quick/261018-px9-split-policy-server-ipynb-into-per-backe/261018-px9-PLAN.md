  <behavior>
    - listening_pids(port) contains the PID of a child that listens on an ephemeral port, and is empty for a free port.
    - start_server + wait_until_ready (TCP mode) returns once the started child binds. The log captures the child's unbuffered prints.
    - Stale-owner case. A decoy listener A owns the port. B is started but never binds. wait_until_ready(B, port, ...) raises RuntimeError naming A's PID ("owned by"). It must not return success just because the port answers.
    - Early exit. A child prints "boom" and exits 3. wait_until_ready raises RuntimeError containing the exit code and the "boom" log tail.
    - Banner. A banner present anywhere in the log (not line 1) passes. A missing banner raises RuntimeError saying the expected launcher banner is absent.
    - Health mode. A tiny stdlib http.server child serves /health {"status":"ready"}. wait_until_ready(health_url=...) returns that dict. A ready predicate that returns False keeps waiting until timeout, then raises TimeoutError and terminates the child.
    - stop_servers(port, patterns=[unique marker]) stops the port's listener and a non-listening process whose cmdline contains the marker. Afterwards listening_pids(port) is empty. It never stops the calling process.
    - process_report(port, expected_marker, proc) prints an OK verdict for the right owner. It raises RuntimeError for a wrong marker, a foreign owner, or nothing listening.
    - log_report prints the last N lines and the numbered lines matching ERROR_PATTERN (Traceback, "Error in StreamActions", beginAllocateToPool).
