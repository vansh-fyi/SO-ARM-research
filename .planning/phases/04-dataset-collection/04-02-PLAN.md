<objective>
Implement the hand-coded waypoint scripted trajectory generator (D-01) and run it to
completion, producing the phase's primary dataset: 100+ successful SOARM demonstrations
across the 3 frozen `libero_spatial` bowl-to-plate tasks in robomimic-schema HDF5, using
the recording infrastructure built in 04-01.

Purpose: DATA-01 requires a scripted collector that records SOARM task completions.
Research confirmed no built-in scripted-expert policy exists in LIBERO/robosuite for
pick-place tasks, and VLA-rollout filtering is ruled out (OFT/pi0 sit at 0% zero-shot
success on SOARM per Phase 3's confirmed baseline) — a hand-coded waypoint state
machine driven by ground-truth object positions is the resolved approach.

Output: `collector.py` (waypoint FSM + full collection driver) and the actual on-disk
dataset: `LIBERO/libero/datasets/soarm_spatial/{task}_demo.hdf5` x 3, ~40 successful
demos each (120 total, 20% buffer over the 100+ requirement, per D-04 resolution).
</objective>

    function (no env/sim access, only numpy math) implementing an 8-phase FSM: "approach" ->
    "descend" -> "grasp" -> "lift" -> "transport" -> "place_descend" -> "release" -> "retreat"
    -> "done". Each phase computes a target 3D point (hover-above-bowl for approach/lift,
    bowl_pos itself for descend/grasp, hover-above-plate for transport/retreat, plate_pos itself
    for place_descend/release) and returns `dpos = clip(target - eef_pos, -0.05, 0.05)` (per
    RESEARCH.md's Pattern 3 worked example — 0.05 is a starting clip magnitude matching OSC_POSE's
    native per-step delta scale; treat exact clearance heights and phase-transition tolerances
    as tunable starting points, not final values — iterate against the real env in Task 3 below,
    the same empirical-tuning workflow Phase 2 used for camera pose tuning). Rotation deltas
    stay `[0, 0, 0]` throughout (top-down grasp, no reorientation needed for this object set).
    Gripper element is `-1.0` (open) for phases before grasp closes, `1.0` (closed) from "grasp"
    through "place_descend", `-1.0` again from "release" onward. Phase transitions when the
    current phase's target is reached within a small tolerance (xy and z separately, since
    horizontal reach vs. vertical clearance need different tolerances) — return the SAME phase
    if not yet close enough, the NEXT phase if close enough. Track `gripper_closed` as an
    explicit input/output boolean so the function stays pure (no hidden state).
