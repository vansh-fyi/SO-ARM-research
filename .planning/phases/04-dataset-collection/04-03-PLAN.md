<objective>
Implement DATA-02's state-based determinism verification and run it against the real
100+-demo dataset produced in 04-02: a cheap states-only check across 100% of demos, plus
a sampled (~10%, min 5, >=1/task) full observation-regeneration check that would catch a
subtler obs-extraction bug the cheap check can't see (D-06's resolved two-tier split).

Purpose: DATA-02 requires that "any recorded demonstration replays frame-identically via
state-setting (not action playback) — deterministic on re-run." This is exactly what
`ControlEnv.set_init_state()` (already used by 04-01's `hdf5_writer.py` to BUILD the
dataset) provides when called again on the SAME recorded state — this plan proves the
round-trip, it does not build a second replay engine. Action-replay (`env.step(action)`
loops) is explicitly the wrong verification method here (LIBERO issue #16 — contact
solver nondeterminism, not what DATA-02 is asking for).

Output: `replay.py` (two verification tiers) and a full verification run against 04-02's
actual on-disk dataset, all green before the phase's UAT.
</objective>
