<objective>
Harden the chunk-drain base with the failure and end-of-episode semantics, and wire the two additive loop edits so an MLLM episode really ends when the model claims completion or the backend keeps failing, and so MLLM backends can own their depth call.

Purpose: MLLM-07 (every value in a chunk is a fresh parse-failure opportunity and no failure may crash, zero-fill or spend per tick), D-18/D-19/D-25 (task_complete), and research conflict C5 (parser rule plus FastFS 429 collision).
Output: edited `base_mllm.py`, new `test_mllm_failure.py`, two additive edits in `run_vla_episode.py`, updated `test_run_vla_episode.py`.

## Phase Goal

**As a** researcher benchmarking general reasoning models as raw-autonomy robot controllers, **I want to** select an MLLM backend with `--backend` and have it turn a task prompt, camera views, depth and joint state into raw absolute joint-target chunks that drive the SO-ARM101 through the unchanged safety validator and logger, **so that** Phase 16 can compare MLLM raw-autonomy behavior against trained VLA policies using per-call audit records instead of guesses.

This slice: a bad model response or a "done" claim now does the right thing in the real loop: hold position, stop spending, end the episode with a recorded reason.

Decisions implemented here: D-00c, D-03, D-06 (depth owned by the backend), D-18, D-19, D-25. Research: conflicts C4 (refusal handled as failed call with stop details logged), C5, Pattern 5, Pattern 8, Pitfalls 4, 12, 15.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model/provider response -> hold queue | Failure responses must never become motion or paid retries |
| run_episode loop <- action source flag | A duck-typed attribute decides episode termination |
| FastFS depth service <- two possible callers | Overlapping depth requests are rejected with 429 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-06 | Denial of service (economic) | persistent provider failure / refusal loop | high | mitigate | chunk_len holds per failure, consecutive-failure cap ends the episode with mllm_backend_failed, post-complete guard blocks any call after a terminal flag; tests assert adapter.calls |
| T-15-07 | Tampering | model claims task_complete then emits motion | medium | mitigate | A strict boolean true holds the entire chunk (D-25) so no unexamined motion follows a done claim; claim logged for Phase 16 false-completion analysis (D-19) |
| T-15-08 | Tampering | termination hook triggered by a non-string or mock attribute | low | mitigate | Hook requires a non-empty str; tests cover None, empty and object values |
| T-15-09 | Denial of service | backend depth call collides with a second depth client (HTTP 429) | medium | mitigate | main() never builds a depth client or DepthRecorder for MLLM backends; the backend owns one synchronous call per chunk (Plan 15-05, 15-06) |
</threat_model>
