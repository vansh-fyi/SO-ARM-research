## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Colab kernel module caching | Re-syncing an updated source file (via the unzip cell) does NOT reload already-imported Python modules in a running Colab kernel. Re-running cells within the same live kernel session silently keeps executing stale (pre-fix) bytecode, producing a misleading repeat of the same error even after a real fix is on disk. | advisory | Always do a genuine **Runtime > Restart session** after any source-file fix before re-running cells that import the changed module — not just re-running the unzip/sync cell. |
| Case-insensitive macOS + gitignored nested LIBERO repo | `LIBERO/` is entirely gitignored by the main repo and is its own nested git repository with separate history. On case-insensitive macOS, writing to `libero/...` (lowercase) is physically the SAME directory as `LIBERO/...`, but git's case-sensitive `.gitignore` matching does NOT recognize `libero/...` as ignored — so files silently get tracked by the MAIN repo under a lowercase path instead of living in LIBERO's own git history. This is pre-existing (from Phase 1), not a new defect. | advisory | Do not "fix" this mid-phase by moving tracked paths — it's an accepted, established convention in this repo already merged multiple times. Only worth revisiting as a deliberate cross-phase cleanup task, never silently during phase work. |
