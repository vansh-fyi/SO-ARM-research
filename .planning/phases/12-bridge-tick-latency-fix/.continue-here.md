## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Parallax-only camera-liveness check | Confirming a stereo recording is "live" by comparing LEFT vs RIGHT within a single snapshot only proves the split is geometrically correct (real parallax exists even in one frozen frame) -- it does NOT prove the camera captures fresh frames over time. This exact mistake was made once this session (UAT test 1's first pass verdict) and only caught because the user pushed back and asked to check the actual episode-recording code. | advisory | Always diff a camera's frames ACROSS TIMESTEPS (step 0 vs step 150 vs step 299, etc.), not just left-vs-right within one instant, before declaring a camera feed "confirmed live". |
| Reprojection error alone doesn't guarantee a trustworthy calibration | A calibration with low-ish reprojection error (2.4-2.7px) still produced a stereo baseline (T) estimate that swung 30% between independent runs on the same physical hardware (which cannot actually change). Baseline should be checked for cross-run consistency, not just reprojection error, before trusting a calibration. | advisory | When judging a new stereo calibration, compare its baseline (T) to a prior run's if one exists -- large disagreement (>~5%) means the calibration hasn't converged yet even if reprojection error looks acceptable. |
| ffmpeg orphan processes competing for the same camera produce silently frozen (not erroring) frames | Multiple un-released ffmpeg subprocesses holding the same AVFoundation device concurrently caused byte-identical frames with no error/crash -- looked exactly like a driver-level freeze. Root cause was two of this session's own new scripts (preview_checkerboard.py, calibrate_with_preview.py) never calling `.release()` on the StereoSplitCamera, even on clean exit. | advisory | Any new script that opens StereoSplitCamera MUST call `.release()` in a `finally` block covering every exit path (normal completion, keyboard interrupt, exception). Check `ps aux \| grep ffmpeg` for orphans before assuming a "frozen camera" is a driver bug. |

_These are advisory, not blocking -- read them before touching camera code again this session, but no formal understanding-check gate is required to proceed._
