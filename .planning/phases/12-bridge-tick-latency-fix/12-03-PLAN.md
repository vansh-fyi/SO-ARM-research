<objective>
Close two of the three live-hardware UAT gaps found in Phase 12's own re-verification
episode (`.planning/phases/12-bridge-tick-latency-fix/12-UAT.md`), both already root-caused
with an explicit fix direction:

**Gap 1 (major):** `run_vla_episode.py`'s `IOLogger` camera_overhead diagnostic recording
opens a second, independent `cv2.VideoCapture` on the AR0144's numeric index -- colliding
with `connect_bridge()`'s `StereoSplitCamera`, which already holds the SAME physical device
open via its own `ffmpeg` subprocess. `stereo_camera.py`'s own docstring documents that the
AR0144 does not tolerate concurrent opens; the second open silently landed on the laptop's
FaceTime camera in the live UAT run. The actual policy input (via `StereoSplitCamera`,
opened by device name) was unaffected -- this is a diagnostic-recording-only bug. Fix: stop
opening a second capture; reuse the already-open `client._stereo_camera` (exposed since
Plan 11-03/`_wire_stereo_split_cameras()`) and log both `read_left()`/`read_right()` frames
as two separate images per step.

**Gap 2 (major):** `run_episode()`'s control loop sends absolute joint-position targets
directly via `robot.send_action()` every tick (default `--control-hz=2.0`), with zero
interpolation anywhere in the per-step loop -- `move_to_positions()`'s P-control smoothing is
only used for the start/e-stop reset move. Fix: interpolate between the previous sent
position and the next target action before sending, executing the interpolated waypoints at
a rate (`--execution-hz`) decoupled from and higher than the observation-fetch cadence
(`--control-hz`), since chunk playback pops from a local queue and needs no network
round-trip except at chunk boundaries (Plan 12-01's `LATENCY-01` gate already restricts
`control_loop_observation()` calls to when the queue is near-empty).

Gap 3 (the blocker-severity stale/similarity deadlock) is a different file
(`control/vla_bridge/robot_client.py`) with zero `files_modified` overlap with this plan --
it is closed by the sibling gap-closure plan `12-04` in the same wave.

required by `LATENCY-03`/`LATENCY-04` can be considered clean, not just literally passing on
three narrow pass criteria while shipping two visible defects.
