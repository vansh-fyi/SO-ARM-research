## Phase Goal

**As a** researcher building the SoARM VLA data/fine-tuning pipeline, **I want to** depth frames recorded in the HDF5 dataset (07-02) to survive conversion into the RLDS/TFDS dataset OpenVLA-OFT actually trains against, **so that** Phase 9's re-fine-tuning run has a real depth-augmented dataset to opt into.

This plan is the depth-to-RLDS slice, extending 07-02's HDF5-level capability one hop further downstream: after it lands, a researcher can run `hdf5_to_rlds()` on a depth-augmented HDF5 and get back a TFDS dataset whose schema — not just its raw bytes — includes depth. This is the final increment needed for DEPTH-03; Phase 9 (TUNE-05) is the separate, later phase that flips `load_depth=True` to actually consume it during training (out of this phase's scope, per 07-RESEARCH.md Pitfall 4).

Depends on 07-02 because it reads the exact `"agentview_depth"` key name / `float32` `(H,W,1)` shape convention 07-02 establishes in the HDF5 schema — this plan does not re-derive that convention, it inherits it verbatim.
