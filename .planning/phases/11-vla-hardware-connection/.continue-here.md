# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: worktree-merge fork-point base — `worktree.cleanup-wave`'s `expected_base` must be the ORIGINAL fork-point commit (the master HEAD at dispatch time), not the agent's current HEAD after it advances through checkpoint continuations. Passing the current HEAD as `expected_base` gets rejected with `base_mismatch` even though it "matches" — the check validates against the true fork point. If a future wave's cleanup fails with `base_mismatch`, re-check the manifest against the actual dispatch-time master commit, not whatever the agent's latest return reported.
- [ ] CONSTRAINT: main-checkout `control/.venv` deps after worktree merge — worktree-created venvs are gitignored and never survive a merge back to the main checkout. After merging any wave whose executor installed new packages (pytest, grpcio, protobuf, lerobot extras, etc.) inside its own worktree venv, you must manually `pip install` those same packages into the MAIN checkout's `control/.venv` before running the post-merge test gate, or tests will fail with `ModuleNotFoundError` that has nothing to do with the actual code.

**Do not proceed until both boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| worktree `expected_base` = current HEAD instead of fork point | Recording an executor's own returned `expected_base` (its current HEAD after checkpoint continuations) into the wave manifest, instead of the master commit the worktree actually forked from | blocking | Always use the master HEAD captured immediately before `Agent()` dispatch as `expected_base` in `worktree.record-agent` / the manifest — never the value an executor happens to self-report after later commits |
| stray un-removable worktree directory after merge | `git worktree remove` can fail with `.git does not exist` after a `cleanup-wave` merge reports success, leaving a "prunable" registration and a leftover directory (containing only gitignored content like `.venv`) | advisory | Run `git worktree prune` then `rm -rf` the leftover directory once `git worktree list` no longer shows it registered — the real work was already merged in the `chore: merge executor worktree` commit, so nothing is lost |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
