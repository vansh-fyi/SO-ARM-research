# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: `resolve_port_identity()` must never use `write_calibration()` as an identity test — a robot-class/id combination with no saved calibration file loads `robot.calibration` as an empty dict, making `write_calibration({})` a silent no-op that never raises, so "no exception" is not proof of identity. The fix (already applied, commit `eb85f22`) compares live `bus.read_calibration()` values against the id's own saved file instead — genuinely read-only. Do not revert to a write-based test.
- [ ] CONSTRAINT: `cv2.VideoCapture`'s AVFoundation backend cannot be trusted to report the AR0144 stereo camera's true 2560x720 resolution on macOS (confirmed unfixed OpenCV bug, opencv/opencv#23368) — it silently serves a lower resolution regardless of explicit `CAP_PROP_FRAME_WIDTH/HEIGHT/FOURCC` requests. The fix (commit `0541458`) captures via an `ffmpeg` subprocess instead. Do not revert `StereoSplitCamera` to cv2 for this camera.
- [ ] CONSTRAINT: numeric AVFoundation device indices (both cv2's and ffmpeg's own) are NOT stable across separate process launches on this machine — confirmed live, the same physical camera showed up at a different ffmpeg index moments apart. `device_map.json`'s `cameras.stereo_overhead_name` (a device NAME string, e.g. `"CCB Camera"`) is the only identifier safe to persist and reuse across processes for the ffmpeg capture path; the numeric `cameras.stereo_overhead` is kept only for the unrelated, non-safety-critical IOLogger cv2 recording caps.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Write-as-identity-test | Using a mutating call (`write_calibration()`) to "test" device identity, where a no-op failure mode looks identical to success | blocking | `resolve_port_identity()` now does a pure read-and-compare; see constraint above |
| Trusting cv2 resolution on macOS | Assuming `cv2.VideoCapture`'s reported width/height reflects the device's real capture mode | blocking | `resolve_cameras()` falls back to a real `ffmpeg`-based capture check (`_verify_stereo_via_ffmpeg`) when no cv2 candidate matches 2560x720 |
| Persisting a numeric AVFoundation index across processes | Assuming a device's numeric index (cv2 or ffmpeg) stays stable between separate script launches | advisory | Stereo camera is now addressed by name (`stereo_overhead_name`); wrist camera still uses a cv2 index since no drift was observed there — re-verify if wrist camera identification ever misbehaves |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
