# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: upstream lerobot observation-similarity deadlock — `lerobot.async_inference.policy_server.PolicyServer._obs_sanity_checks()` silently skips running inference on any observation whose joint-space state is within ~1° of the last one it actually processed (see `observations_similar()`), unless a `must_go` flag forces it through. If the robot isn't moving, every new observation looks "the same" to the server, so it never runs inference again — a self-reinforcing deadlock. This matches unresolved upstream issues [lerobot#2356](https://github.com/huggingface/lerobot/issues/2356), [#2374](https://github.com/huggingface/lerobot/issues/2374), [#1500](https://github.com/huggingface/lerobot/issues/1500). Do not assume a fresh retry will just work — watch closely whether the very first real action actually executes.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Silently-discarded diagnostic flags | `BridgeActionSource.get_action()` used to throw away `pop_validated_action()`'s flags, making "queue empty" and "genuine valid action" indistinguishable in `episode.jsonl` (both logged `@unknown`) | advisory | Fixed in commit `343fa28` — flags now surface through `model_version`. If you add new bridge-path code, always thread flags/diagnostics through to the log rather than collapsing them. |
| Assuming a running background thread exists because a function returns cleanly | `connect_bridge()` called `client.start()` (handshake only) and returned successfully, but `client.receive_actions()` — the thread that actually drains the gRPC action stream into `action_queue` — was never started. No error, no crash, just permanently empty queue. | blocking | Fixed in commit `343fa28`. When wrapping a library's client object, check whether *all* of its background threads/workers are actually started, not just whichever ones the "happy path" call chain appears to imply. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.

Fixed by adding a `stale_threshold_s` parameter to `validate_action()` and defaulting `pop_validated_action()` to `STALE_ACTION_S`.
  - **Finding 3 (not yet fixed — see blockers below)**: Even after both fixes, the robot still never moved by end of session. Root cause identified via web research + reading installed `lerobot` source: the PolicyServer's observation-similarity filter creates a self-reinforcing deadlock when the robot isn't moving.
