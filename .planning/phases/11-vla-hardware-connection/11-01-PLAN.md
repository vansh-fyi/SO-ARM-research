<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any candidate action → servo bus | `raw_action` may originate from a scripted source (Plan 11-02), a network bridge (Plan 11-03/04), or a bug anywhere upstream — it must be treated as untrusted input regardless of source |
| live calibration file → joint limits | `load_joint_limits_deg()` trusts `~/.cache/huggingface/lerobot/calibration/robots/so_follower/soarm_follower_02.json` as ground truth; if that file is stale/corrupted the derived limits are wrong |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Tampering | `safety_validator.validate_action()` | critical | mitigate | Every joint value is range-clamped against `JOINT_LIMITS_DEG`, per-step-displacement-clamped, and NaN/inf-rejected (holding current position) before any caller can pass it to `send_action()`; `test_safety_validator.py` pins all four behaviors |
| T-11-02 | Tampering | `action_contract.load_joint_limits_deg()` | medium | mitigate | Limits are re-derived from the live calibration file at call time (not hardcoded permanently) so a recalibration event is picked up automatically; `wrist_roll`/`gripper` are pinned to fixed, non-calibration-derived constants specifically because their calibration entries are known placeholders (Pitfall 1/4) |
| T-11-03 | Denial of Service | `validate_action()`'s stale-observation path | low | accept | Aggressively holding position on any `obs_age_s > 1.0s` is a deliberately conservative default that may cause visible "stalling" if tuned too tight; accepted for this research phase since fail-safe (hold) is the correct failure mode, not fail-open |

</threat_model>
