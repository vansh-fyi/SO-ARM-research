<objective>
Close CAMFIX-03: add a `sha256` provenance hash to the frame-record dict `IOLogger.capture_stereo_frame()`/`capture_camera_frame()` already return for every `policy_camera1`/`policy_camera2`/`policy_camera3` step, with an explicit client-side-only-provenance disclosure (D-08 through D-11). This is a complete, independently-verifiable unit orthogonal to this phase's camera-resolution work -- `io_logger.py` doesn't open or resolve cameras, it only records already-captured frames.

Purpose: Per D-07, most of "what was actually sent" is already captured by existing Phase-12 code (`BridgeActionSource.get_action()`'s `observation` dict, `run_vla_episode.py`'s `policy_camera1/2/3` PNG saves). The genuinely missing piece is a content-integrity hash proving the client's local copy of each frame, plus the disclosure that this can never prove server-side receipt.

Explicitly excluded per D-09: no separate/redundant thumbnail image is added. Since the full-resolution frame is already saved as a PNG per step (Phase 12 work, unchanged by this plan), a second smaller thumbnail copy of the same content would add no real capability -- this plan adds ONLY the `sha256` field, nothing else.
Output: `sha256` field on every `_record_frame()`-routed dict; docstring disclosure; full test coverage.
</objective>
