<objective>
Close the sole remaining 05-UAT.md gap (status: diagnosed, severity: blocker): `OFTBackend.predict()` crashes on Colab GPU with `RuntimeError: split_with_sizes expects split_sizes to sum exactly to 12 ... but got split_sizes=[3, 3]` whenever both camera views are supplied. Root cause (from the UAT diagnosis): `OFTBackend.__init__` never calls `self.model.vision_backbone.set_num_images_in_input(2)` after loading the checkpoint, so the model's vision backbone stays in its default single-image state and rejects the 12-channel concatenated `pixel_values` tensor `predict()` builds. A second, non-crashing but incorrect defect ships alongside it: `predict()`'s `primary`/`extra_views` assignment is inverted relative to upstream's convention (primary should be the third-person `agentview` frame, not the wrist `eye_in_hand` frame) -- channel order is baked into the checkpoint's training, so this must be corrected too, per 05-UAT.md's diagnosis.

Purpose: Make SPAT-02 ("all camera views are passed as input to the VLA during inference") true as an actually-working behavioral fact for OFTBackend on the real checkpoint, not just a source-level pattern that crashes at runtime.
Output: `oft_backend.py`'s `__init__` activates the checkpoint's documented `num_images_in_input=2` mode; `predict()`'s image ordering matches upstream (agentview primary, eye_in_hand secondary); a new local mock-based test suite (`test_oft_backend.py`) proves both fixes without requiring GPU/torch. Per this project's `human_verify_mode: end-of-phase` config, the real-checkpoint Colab confirmation is not a blocking mid-plan checkpoint -- it is documented as a `<human-check>` re-verification step in this plan's `<verification>` block, to be exercised via the standard end-of-phase UAT loop (the same loop that surfaced this gap).
</objective>
