<objective>
Build the shared foundation for both Gemini-family backends (VLAB-01 Gemini Robotics, VLAB-02 Gemini Robotics 2), sequenced LAST among the transport lanes per D-05 ("the 2 cloud-API backends... last") since this is the genuinely new, non-Colab-bridge transport lane (D-02: direct HTTPS from the control-loop machine, no Colab hop).

14-RESEARCH.md's most important finding for this plan: the full native-action-output Gemini Robotics and Gemini Robotics 2 VLA APIs are early-access-partner-gated, NOT publicly available -- only Gemini Robotics-ER 2 (embodied reasoning: points/bounding boxes/trajectories in JSON, not joint/motor commands) is public. Per 14-CONTEXT.md D-02's explicit supersession, both VLAB-01 and VLAB-02 build against this public ER 2 API plus a local conversion layer that turns its spatial output into a bounded joint-space action -- this is architecturally different from the other 11 backends' direct trained-action-output path and must be documented as such everywhere it appears (module docstrings, `model_version` strings, `io_logger` entries), never silently presented as equivalent.

Purpose: one shared base class + one shared ER-to-action conversion module that Plans 14-14/14-15's thin per-model subclasses both build on -- avoids duplicating the HTTPS/auth plumbing and the conversion primitive twice.
Output: `base_gemini.py` (GeminiActionSourceBase), `er_conversion.py` (the ER-output-to-joint-action primitive), `google-genai` added as a human-verified dependency.
</objective>
