<objective>
Prove the Wave 1 foundation actually works by wiring the two backends that already exist today (`ScriptedActionSource`'s dry-run path and SmolVLA's live bridge path) through the new `BACKEND_REGISTRY`, and add the `--backend` CLI flag (D-06) that makes backend selection explicit and extensible. This is the plan that turns `run_vla_episode.py`'s current hardcoded `if args.server_address: ... else: ...` branch into a single `BACKEND_REGISTRY[args.backend](...)` dispatch call -- the concrete mechanism PIPE-01 requires ("switching between any of the 13 VLA-style backends requires no changes to run_vla_episode.py's shared control loop").

Backward compatibility is non-negotiable here: every existing invocation of `run_vla_episode.py --server-address ... --checkpoint ...` (no `--backend` given) must keep working identically -- this plan adds a backward-compat shim (an omitted `--backend` auto-resolves to `"smolvla"` when `--server-address` is given, `"scripted"` otherwise) rather than silently changing already-documented CLI usage.

Purpose: this is the one plan every later Wave 3+ backend plan's `<read_first>` points back to as "the CLI/registry contract to plug into" -- it must be exactly right before 12 more backends build on it.
Output: `--backend` CLI flag; `BACKEND_REGISTRY` populated with `"scripted"` and `"smolvla"`; `main()`'s branch replaced by registry dispatch; a durable, wave-count-agnostic conformance test.
</objective>
