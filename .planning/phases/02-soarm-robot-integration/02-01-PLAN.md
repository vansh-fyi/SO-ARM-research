# Plan 02-01: Validation Harness + Vendored SO101 Assets + Arm MJCF Adaptation

## Phase Goal

**As a** VLA researcher, **I want to** select the SOARM SO101 robot by name in LIBERO and run libero_spatial tasks with it — with stable physics and correct rendering, **so that** the Phase 3 inference loop can drive SOARM from language prompts instead of the stock Panda.

<objective>
Create the phase's end-to-end validation harness first (MVP failing-test-first; Wave 0 gap `explorations/soarm_sanity.py` per 02-RESEARCH.md Validation Architecture), then vendor the SO101 hardware description from TheRobotStudio/SO-ARM100 with a pinned commit SHA, and produce the robosuite-1.4/MuJoCo-2.3.7-compatible arm MJCF (`robot.xml`) following the 9-item adaptation checklist from 02-RESEARCH.md Pattern 1.

This implements the MJCF half of ENV-04. Local-only work per D-09 (no GPU, `MUJOCO_GL=glfw`, `libero` conda env). Geometry is vendored, never re-modeled (locked premise in CONTEXT.md; D-05 for the gripper geoms which stay in the vendored source until plan 02-02 splits them out).

Purpose: without a compiling arm MJCF and a harness that measures every later success criterion, nothing downstream (classes, registration, physics tuning, Colab verification) can be verified incrementally.
Output: `explorations/soarm_sanity.py` (RED on missing pieces by design), `assets/robots/soarm101/` with adapted `robot.xml`, pristine source XML, 13 vendored STLs, and `VENDOR.txt` provenance.
</objective>
